# 发布与更新

官方源码仓库：<https://github.com/MGHYGitHub/ClickFlow>。最新版：<https://github.com/MGHYGitHub/ClickFlow/releases/latest>。

## 使用者获取更新

在「偏好设置 → 版本与更新」检查。版本信息来自 GitHub API 的 `repos/MGHYGitHub/ClickFlow/releases/latest`，只接受正式稳定版本，按数字比较主版本、次版本和修订号。不会将 3.10.0 误判为早于 3.9.0，也不会推荐降级。没有新版本时显示当前版本已是最新。

GitHub API 返回 403 / 429 限流状态时，更新服务读取官方 `releases/latest/download/update.json`。此文件由发布脚本生成，并随每个正式 Release 上传，无需额外服务器；其版本、EXE 文件名、地址与大小仍按相同规则验证。

检测到更新后可以打开发布说明或下载新版 EXE。只接受官方仓库的 HTTPS Release 资产，必须同时具有对应的 `ClickFlow-<版本>-win-x64.exe` 与 `SHA256SUMS.txt`。下载以临时文件写入，完成后核对长度及 SHA-256，再保留可用 EXE；失败或取消不保留未完成文件。SHA-256 防止文件损坏，信任来源仍为官方 GitHub 账号与 HTTPS，不替代数字签名。

下载目录为 `%LOCALAPPDATA%\ClickFlow\Updates\<版本>`。点击「打开下载目录」，退出软件，将新版文件改名为 `ClickFlow.exe` 后替换旧版。任务配置位于 `%LOCALAPPDATA%\ClickFlow\workflow.json`，替换程序不会删除配置。使用了 `--data-dir` 的用户，更新也会放在该自定义目录下的 `Updates`。

检查和下载由按钮触发，不在启动时后台联网；不上传配置、录制或统计。遇到离线、缺少资产或校验失败会显示原因；可稍后重试或从官方 Releases 页面下载 ZIP。程序不会自动提权、执行下载文件或替换正在使用的程序。

## 版本号与文件约定

`Directory.Build.props` 是唯一产品版本来源，例如 `3.1.0`。程序集和文件版本生成 `3.1.0.0`；界面显示程序集产品版本。`app.manifest` 中 `1.0.0.0` 仅是固定的 Windows 激活身份，不是产品更新版本，无需随发布修改。

正式发布标签必须为 `v<版本>`，例如 `v3.1.0`，对应 Release 必须发布为稳定版。不接受前导零或预发布后缀。

| 资产 | 用途 |
| --- | --- |
| `ClickFlow-3.1.0-win-x64.exe` | 可直接运行、内置 .NET 的 Windows x64 软件；内置更新器下载此文件 |
| `ClickFlow-3.1.0-win-x64.zip` | EXE、README、文档、项目及运行时许可证 |
| `ClickFlow-3.1.0-source.zip` | 完整源码、测试、主题、图标、文档与构建 / 发布脚本 |
| `update.json` | 与 GitHub Release 结构一致的备用更新元数据，用于 API 限流场景 |
| `SHA256SUMS.txt` | 上述四个文件的 SHA-256；小写十六进制、两个空格、准确文件名，UTF-8 无 BOM |

源代码 ZIP 排除 `.git`、`bin`、`obj`、`artifacts`、预览配置和日志。GitHub 自动生成的 Source code ZIP / tar.gz 也可用于取得版本标签下源码。

## 本地构建与打包

在 Windows 上安装 .NET 10 SDK，打开仓库目录执行：

```powershell
./build.ps1
./scripts/package.ps1
```

第一个命令构建解决方案并运行两组回归测试；第二个命令重新构建、测试、发布独立单文件 EXE，按版本打包到 `artifacts/release/`，并生成更新元数据与校验清单。`artifacts/publish/win-x64/ClickFlow.exe` 是原始发布文件。业务代码没有第三方 NuGet 依赖，发布所需微软运行时从 NuGet 恢复。

已执行 `./build.ps1 -Publish` 后，可用 `./scripts/package.ps1 -SkipBuild` 仅重新打包。脚本会拒绝 EXE 文件版本与源码版本不一致的情况；仅改资源或代码而未改版本时，仍须自行重新构建，版本检查不验证源码新旧。`-NuGetSource <地址或目录>` 允许使用预先下载的官方 NuGet 源；`-OutputDirectory <目录>` 可更改资产输出位置。

发布前还应运行独立包冒烟检查：

```powershell
./artifacts/publish/win-x64/ClickFlow.exe --smoke-test --data-dir "$env:TEMP\ClickFlow-smoke"
```

检查它正常退出，测试目录中生成 `workflow.json` 且没有 `errors.log`。此模式不向桌面发送输入。实际输入、录制和多屏检查见 [验收记录](验收记录.md)。

## 发布下一版本

1. 修改 `Directory.Build.props` 中版本，例如 `3.1.1`；为变化补充回归测试，并新增 `docs/releases/v3.1.1.md` 说明。
2. 提交并推送至 `main`，确认「Build and test」工作流通过。
3. GitHub 仓库打开 **Actions → Publish release → Run workflow**，选择对应源码分支，填写 `v3.1.1`。
4. 工作流校验版本和发布说明，构建、测试、打包并冒烟检查；创建草稿 Release、上传全部资产，成功后将其公开并设为最新版本。
5. 在旧版本中手动「检查更新」，验证版本、发布说明及新版下载。GitHub 无需额外服务器。

普通 push 和标签 push 不会自动发布，避免与人工首发重复；Release 工作流只接受手动触发。工作流使用 GitHub 提供的短期 `GITHUB_TOKEN`，不需要在仓库中保存个人令牌。版本标签若已指向其他提交会被拒绝；已存在同名 Release 不会被覆盖。上传中途失败留下草稿时，检查草稿资产后手动完成或删除该草稿再重跑，不能对已公开版本替换不同的构建。

更新模块固定指向官方仓库。Fork 若希望独立发布，需同时修改更新服务中的仓库常量、`Directory.Build.props` 仓库地址、发布脚本中的更新地址和本文 / README 的链接，并保留发布资产与校验格式。
