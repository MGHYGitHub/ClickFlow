# 旧版审阅与迁移

审阅日期：2026-10-11。只读分析了两个 GitHub 仓库的实际源码，没有运行旧程序或触发桌面点击。本机旧版源文件与第一仓库主文件的 SHA256 相同。

## 重构取舍

| 来源 | 保留的产品能力 | 重新实现的部分 |
| --- | --- | --- |
| Python AutoClicker | 多点位、独立次数/间隔、组合键、捕获坐标、暂停、倒计时、随机偏移、主题、托盘 | 将约五千行单文件拆成界面、执行引擎、Windows 输入、配置存储；所有等待可取消；单实例任务状态 |
| Java Auto-clicker | 简洁点位列表、滚轮、鼠标与键盘录制、回放、运行控制、命名点位与配置 | 用 Windows 原生输入和热键代替 JVM/Robot/JNativeHook；维护按下状态并在停止、异常后释放；录制与任务分开存储 |

新版本采用 C#、.NET 10、WPF 和 Win32。目标是 Windows 10/11，WPF 对多窗口、键盘焦点、DPI、托盘和桌面快捷键的支持成熟，界面可以用模板实现简约扁平风格；核心运行逻辑不依赖 WPF，便于用假输入驱动测试。这里选择 Windows 专用实现，不承担跨平台运行时的体积与行为差异。

## 在旧源码中确认的问题

Python 文件为 `AutoClicker_2.5.py`：

- 2143 行停止任务后立即允许重新启动，2115 行会清除共享停止事件；旧线程仍在 `sleep` 时重新启动可能产生同时执行。
- 2315、2322、2329 行使用不可中断等待，2237 行重复点击循环没有检查暂停。
- 2391 行全局快捷键回调和 2860 行日志方法直接访问 Tk 控件；工作线程/UI 数据混在一起。
- 1937–1959 行“导入配置”丢弃 `action_type` 和 `keys`，而 2035 行自动加载保留这些字段，导致键盘步骤被误读为鼠标步骤。
- 2479 行将每次点击后 3 秒都视为程序移动，高频点击时难以识别人工鼠标移动。
- 2175 行仅在任务开始时激活目标窗口，不能保证执行过程中仍点在同一应用；激活失败也绕过后面的清理逻辑。
- 2241 行键盘动作与 2283 行鼠标动作计数不一致；2325 行中断也会增加完成循环数。
- 原程序保存的只是点位数组，运行设置没有保存；文件直接覆盖写，未做原子替换或版本校验。

Java 文件为 `src/main/java/com/example/autoclicker/AutoClickerApp.java`：

- 1192–1213 行明确了 Properties 文件格式，名称和组合键使用 Base64Url 编码；点位和录制数据分别存储。
- 1228–1246 行加载会对负延迟/次数进行截断，也可能跳过字段数量不符的点位。新版本对畸形数据报错，避免悄悄丢动作。
- 885–895 行回放直接驱动 Robot，917 行通过原生键码的显示名称转换按键；不能把持久化的 JNativeHook 码直接当 Windows VK 使用。
- 958–963 行每个点位执行前有独立等待，滚轮量是 Java 的格数。新版本统一采用毫秒和 Windows 滚轮增量。

源码入口：[Python 项目](https://github.com/MGHYGitHub/AutoClicker)、[Java 项目](https://github.com/MGHYGitHub/Auto-clicker)。

## 新配置与保存方式

新文件采用 JSON，必须含 `schemaVersion: 1`，字段名称为 camelCase，动作和鼠标键使用字符串枚举，例如 `"kind": "hotkey"`、`"button": "left"`。`steps` 与 `recording` 独立，保存的文件不会自动执行。

加载拒绝未来版本、未知字段、重复字段、无效枚举、不合法时间或次数，以及超过 16 MB 的文件。保存前先校验并序列化，然后写入同目录临时文件并落盘；已有文件使用原子替换，前一个完整版本保留为同路径加 `.bak`。不采用“删除旧文件再复制”回退。加载损坏文件会报错，不自动用备份覆盖用户的现有文件。

## Python JSON 迁移

原程序有两种真实格式：

```json
[[120, 240, "保存按钮"]]
```

```json
[
  {"x":120,"y":240,"name":"保存","button":"left","delay":0.4,"click_count":2,"click_interval":0.1,"keys":"","action_type":"click"},
  {"x":0,"y":0,"name":"快捷键","button":"keyboard","delay":1.0,"click_count":1,"click_interval":0.1,"keys":"ctrl+s","action_type":"keyboard"}
]
```

| 旧字段/行为 | 新配置 |
| --- | --- |
| x、y、name | 原样保留，允许负坐标 |
| button=left/right/middle | 对应鼠标按键 |
| action_type=keyboard，keys | Hotkey 和原组合键文本；不会退化为点击 |
| click_count | Count |
| click_interval，单位秒 | IntervalMs，四舍五入到毫秒 |
| delay，单位秒 | 在当前动作后插入 Wait；DelayMs=0，IntervalMs=旧 delay |
| 最后点位的 delay | 原执行器忽略，新版也不额外增加等待 |
| 原循环之间固定 1 秒 | CycleDelayMs=1000 |
| 键盘动作的 click_interval | 原键盘分支未使用，新版迁移为 0；引擎仍有最小让出时间 |

原始数组没有循环、主题、窗口绑定等设置，无法从中恢复未保存的信息。迁移默认使用一次循环、三秒倒计时。额外接受 `{ "points": [...], "settings": {...} }` 或 `click_points` 包装；可识别设置为 `loop_count/loop`、`countdown`、`random_offset/random_offset_px`、`random_delay`、`base_delay`、`click_count`、`default_button`、`theme`。未知设置会报错，原文件保持不变。Python 旧版零循环代表不执行，因此拒绝将其转换成新版的“无限循环”。

键盘组合必须是单组，例如 `Ctrl+S`。`ctrl+a, ctrl+c` 这样的顺序表达式不能安全归并成一次按键，导入会提示拆分。F2/F3/F4/F6/F7 是新程序控制键，不允许作为任务按键或录制回放按键。

额外包装中的 `random_delay` 必须为零。旧含义是点击间隔的正负随机偏移，新含义是动作后的非负随机附加等待，两者不能等价转换；非零值会明确报错，需要在旧配置副本中设为零，导入后重新设置随机等待。原程序真实保存的点位数组不包含这个设置，不受此限制。

旧版 PyAutoGUI 的隐式暂停和系统调度开销不是配置字段，不作为旧计时值迁入。新引擎也不承诺硬实时精度。

## Java Properties 迁移

实际保存格式如下，其中 `<名称>` 和 `<组合键>` 是 UTF-8 的 Base64Url：

```properties
version=1
default.startDelayMs=0
default.intervalMs=100
default.clicks=1
task.cycleLimit=3
points.count=1
point.0=<名称>,120,240,200,100,2,HOTKEY,1,<组合键>
recording.count=2
recording.0=KEY_PRESS,0,0,0,30,30,0
recording.1=KEY_RELEASE,0,0,0,40,30,0
```

`point.i` 的九段分别为 name、x、y、startDelayMs、intervalMs、clicks、actionType、wheelSteps、hotkey。同时兼容六段命名旧格式，以及五段未命名旧格式。`recording.i` 为 type、x、y、button、delayMs、keyCode、wheelAmount，并兼容不含后两个字段的旧录制；若该动作实际需要缺失字段则报错。

| Java 行为 | 新配置 |
| --- | --- |
| LEFT_CLICK / RIGHT_CLICK | Click + 对应鼠标键 |
| WHEEL | Scroll；Java 正数向下，转换为 `WheelDelta = -120 × wheelSteps` |
| HOTKEY | 每次重复展开为 Move + Hotkey，组合键文本解码保留 |
| 点位 startDelayMs | 步骤执行前 DelayMs |
| MOVE / PRESS / RELEASE | Move / MouseDown / MouseUp |
| KEY_PRESS / KEY_RELEASE | KeyDown / KeyUp，经明确键码表转换 |
| 录制 delayMs | 每个录制动作执行前 DelayMs |
| task.cycleLimit=0 | 无限循环，与 Java 原行为相同 |
| default.intervalMs/default.clicks | 快速连点默认间隔和次数；各点位自己的值完整保留 |
| default.startDelayMs | 原来只是新增点位的模板值，不是任务启动等待；大于零时以禁用的参考等待行保留，可查看或删除，不会执行 |

Java 录制按键映射核对了 JNativeHook **2.2.2** 的 `NativeKeyEvent.java`：例如原生 `30 / 0x001E` 是 A，映射为 Windows `65 / 0x41`。实现有常用字母、数字、修饰键、导航、F 键及部分媒体键白名单；不确定的键码、侧键或不支持的动作会明确拒绝，不按原数值猜测。鼠标编号按旧 Java 回放规则保持 1=左、2=中、3=右。

Java 组合键点位会按重复次数展开为“移动到原坐标，再发送组合键”，首次移动前等待原 startDelayMs，后续移动前等待原 intervalMs（与旧版一致，至少 10 ms）。超过 50,000 个动作的展开会报错，不生成部分任务。
