# 为什么选 C#、.NET 10 和 WPF

这次需求是 Windows 10 / 11 的本地输入自动化工具：Windows 原生能力和可靠任务控制比跨平台更重要。C# 可以直接调用 Win32，异步取消和类型校验也适合需要及时暂停、停止的执行器。

| 方案 | 对本项目的适配 |
| --- | --- |
| C# + WPF | 成熟桌面窗口、托盘、全局热键与 DPI 支持；可重绘控件成现代扁平风格；可打包独立 exe。本次选择。 |
| C# + WinUI 3 | Fluent 外观更接近 Win11，但部署和窗口集成需要更多 Windows App SDK 工程工作；本工具没有必要为此增加依赖。 |
| C++ + Qt | 适合已有 C++ 团队，性能和桌面控件成熟；本工具的瓶颈在目标程序与系统输入，C++ 的额外复杂度收益有限。 |
| Rust + Tauri | 后端与 Web 界面可分离，但仍需要 Win32 原生桥接、WebView 和前端工具链。 |
| Python / Tkinter | 很适合快速原型，但旧版已经在单文件 UI / 线程 / 配置耦合处积累维护问题，现代控件一致性也需要大量手工工作。 |
| Java / Swing | 旧版实现了很有价值的录制能力，但 Windows 专用工具无需继续携带 Java UI 与原生桥接层。 |

WPF 不意味着沿用默认陈旧外观。新版用动态主题资源、统一控件模板、清晰留白、圆角卡片和原生窗口边框；保留 Windows 用户熟悉的缩放、任务栏与标题栏行为。

## 从旧版提炼的设计

Python 版的价值在每步独立参数、快捷坐标捕获、运行控制、随机化与托盘；Java 版的价值在鼠标 / 键盘录制、时序保存与编辑。新版把三种入口统一成一个 ActionStep 和 ExecutionPlan，避免多套执行器在暂停、停止和统计上出现不同规则。

程序依赖方向为 Desktop → Core。Core 不引用 WPF、WinForms、Win32 或任何录制钩子。IInputDriver 将调度与真实输入隔离，自动化测试可以证明时序和取消逻辑而不点击桌面。输入层只有它负责 Windows 坐标、键码和释放状态。

UI 使用轻量事件处理连接 Core 与服务，没有额外引入 MVVM 框架。后续页面和插件增长时可将页面状态拆成独立 ViewModel；不会把调度逻辑重新放入窗口代码。

每次运行复制配置，拥有独立取消源；状态经历倒计时、运行、暂停及完成 / 停止 / 失败。长等待以可取消短片段实现；释放输入完成后才允许新运行。录制和回放互斥，录制回调先排队后交给 UI，避免在系统钩子里做文件 I/O 或显示对话框。

配置是版本化 JSON，并在保存前验证，采用同目录临时文件和原子替换。未知版本与不能安全转换的旧数据显式失败。没有自动上传或启动时执行旧任务。

版本检查由独立更新服务负责，主动查询 GitHub 正式版并按数字比较版本。新版下载使用临时文件、大小限制与 SHA-256 完整性校验，成功后才保存为 EXE；由用户退出软件后替换文件。更新流程不接触工作流配置，网络失败也不会影响已保存任务。
